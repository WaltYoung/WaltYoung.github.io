基于Qwen3-14B基座模型进行思维链微调的可解释ICD-10病案编码专家模型

发表于2026-10-12|更新于2026-10-12|AI病案编码

Qwen3-14B ICD-10 病案编码思维链微调技术文档

目标：在 Qwen3-14B 模型上，通过 LoRA + 思维链（Chain-of-Thought）监督微调，构建可输出 ICD-10 / ICD-9-CM-3 编码结果及依据的病案编码专家模型。

概述

业务目标

将大模型微调为资深病案编码专家，输入结构化/半结构化病历后，自动输出：

输出项 标准
主要诊断及 ICD-10 编码 《疾病分类与代码国家临床版》
次要诊断及 ICD-10 编码 《疾病分类与代码国家临床版》
主要手术/操作及 ICD-9-CM-3 编码 《手术操作分类代码国家临床版》
编码选择依据 基于病历原文 + 编码规则的可追溯说明
异常场景 逻辑不充分时输出「需人工干预」预警

技术路线

核心特点：

  • 使用 Unsloth 加速训练与推理
  • 训练样本为 System Prompt + 病历 + <think>思维链</think> + 最终答案
  • 推理时开启 enable_thinking=True，保留可解释推理过程

环境与依赖

组件 用途
PyTorch + CUDA 模型训练与推理
Unsloth (FastLanguageModel) 高效加载、LoRA、推理加速
HuggingFace datasets 数据集加载与 map 转换
TRL (SFTTrainer / SFTConfig) 监督微调
Transformers (TextStreamer) 流式生成与解码
llama.cpp GGUF 量化导出
Ollama 本地推理服务

加载代码要点

LoRA 配置

通过 FastLanguageModel.get_peft_model 注入 LoRA：

参数 取值 说明
r 8 LoRA 秩（可选 8/16/32/64/128）
lora_alpha 16 缩放系数，通常约为 2 * r
lora_dropout 0 防过拟合；复杂任务可适当提高，建议 ≤ 0.5
bias "none" 不训练偏置（Unsloth 优化路径）
use_gradient_checkpointing True 降低显存，适合长上下文
random_state 3407 随机种子
use_rslora False 未启用 Rank-Stabilized LoRA
loftq_config None 未启用 LoftQ

Target modules（注意力 + MLP 全覆盖）：

  • Attention：q_proj, k_proj, v_proj, o_proj
  • MLP：gate_proj, up_proj, down_proj

System Prompt 设计

代码中定义了超长 PROMPT，将模型角色、编码标准、决策树与输出格式固化为 System Message。

角色与标准

  • 角色：资深病案编码专家
  • 诊断标准：ICD-10 国家临床版
  • 手术标准：ICD-9-CM-3 国家临床版
  • 硬约束：禁止输出标准库外名称/编码；禁止将出院诊断直接当作分析依据

编码思路（决策流水线）

  1. 入院目的拆分
    • 随诊检查判定（含排除条件：计划性治疗、诊断性再评估、阳性新发现）
    • 按历史治疗方式细分随诊编码（术后 / 放化疗后等）
  2. 诊断明确与核实
    • 数据源：主诉、现病史、病理/影像/手术/操作记录
    • 非肿瘤：按系统分析（含肠梗阻路径 A/B）
    • 全身性肿瘤：以细胞分型为编码依据
    • 部位肿瘤：解剖亚部位 + 分布类型（单一 / 交搭跨越 / 多处 / 复合癌）
    • 乳腺部位：钟表法 → 象限/编码部位映射
  3. 治疗方式核实
    • 手术 vs 非手术（化疗 / 放疗 / 同位素 / 免疫 / 靶向 / 内分泌 / 支持）
    • 术前/术后判定；多治疗时优先级：放疗 > 免疫 > 靶向 > 化疗
  4. 诊断与治疗逻辑匹配
    • 匹配正确 → 输出主要/次要诊断与手术操作
    • 不充分或错误 → 「预警：无法编码，需人工干预」

训练配置

使用 TRL SFTTrainer：

超参 取值 说明
dataset_text_field "text" 训练文本字段
per_device_train_batch_size 2 单卡 batch
gradient_accumulation_steps 4 等效全局 batch ≈ 8（单卡）
warmup_steps 5 学习率预热
max_steps 200 步数制训练（也可改 num_train_epochs）
learning_rate 5e-6 较低 LR，适合已微调基座继续训练（通常为[1e-5,3e-5]）
logging_steps 2 日志频率
optim "adamw_8bit" 8bit AdamW，省显存
weight_decay 0.01 权重衰减
lr_scheduler_type "cosine" 余弦退火
seed 3407 可复现
output_dir "outputs_1202_think" checkpoint 目录
report_to "none" 未接入 WandB 等

乳腺验证集批量评测

  • 验证用于测试的 PID 列表：.../ocr_pdf/乳腺/validationSetPID.txt
  • 提取病历文件：递归匹配 *final2*.json
  • 对照思维链：对应 *cot_results6*.json
  • 流程：
    1. 读取用于测试的指定 PID 的病历，剔除医生诊断描述等答案字段
    2. 用 System Prompt + 病历生成
    3. 取 </think> 之后的正式答案
    4. 正则抽取「疾病名称 / ICD-10编码」
    5. 与标准比对，将测试结果写入 test_results_乳腺.csv
  • 匹配规则：疾病名称全等，且预测编码包含于金标准编码，且无「预警」字样 → 记为「匹配」

训练实践注意点

  1. 长上下文成本高：max_seq_length=20480，务必开启梯度检查点，并关注多卡 balanced 负载。
  2. 继续微调学习率宜低：当前 5e-6，避免冲掉已有 ICD 能力。
  3. 思维链质量决定上限：训练依赖 cot 字段质量；<think> 格式需与推理侧 enable_thinking 一致。
