DELETE、TRUNCATE和DROP在删除行为上的区别

DELETE
语法：DELETE FROM table_name [WHERE condition]
DELETE 标记符合条件的数据，再由 Purge 线程在系统空闲时彻底删除已标记的数据。
DELETE 删除大量数据后，会存在碎片，需要整理回收碎片空间

TRUNCATE
语法：TRUNCATE TABLE table_name
TRUNCATE 删除全表数据，回收所占表空间。

DROP
语法：DROP TABLE table_name
DROP 删除全表数据和表结构，回收所占表空间。

注意：

  1. 操作会创建临时表，在磁盘空间紧张时（剩余空间不足表大小的2-3倍），建议先扩容再操作
  2. 操作会锁表，并引起IO突增，适合在业务低峰期执行

配置优化

设置Binlog日志最大大小

较小的max_binlog_size（如 100 MB）会导致 binlog 频繁切换，增加磁盘 I/O 和清理触发频率；但过大的 binlog（如 2GB+）在清理、复制异常时可能带来更长的恢复时间或占用更多临时空间。

故建议设置max_binlog_size为1GB

首先，查看Binlog日志的最大大小

由下图可见，max_binlog_size的值为104857600，即100MB（默认值）
